How a pin works

The hub stores references, not files. Each listed version binds a tag to the exact commit and file contents that passed.

What the checks mean
1An author tags a release

The pack stays in the author's own GitHub repository, at a tag such as v1.0.0.

2The hub checks it

Rendering with Copier's unsafe=False, then each profile's commands: uv sync, ruff, mypy, pytest.

3The listing records the pin

Tag, 40-character commit, and a SHA-256 digest over every file's path and bytes.

4You copy one command

pytemplate-uv refuses the pack if the tag moved or any file changed, and writes nothing.

what a refusal looks like
Error: Template pack 'gh:acme/sample-pack' at v1.0.0 has digest 9257…, not the pinned digest. Nothing was written.

What the labels mean

Listed does not mean safe. A generated project's dependencies, build backend, and tests run code when you use them, so read a pack first.

LabelMeansDoes not mean
ListedThe pack passed the automated checks at this commitSafe, reviewed, or endorsed
ReviewedThe named maintainer reviewed this exact commitSafe or free of bugs
lifecycle passedThe commands passed with default answers, at the time of the checkOther answers or components work
licenseThe submitter's declaration, and a license file existsThe hub checked the license text

Your team starts the same project every month. Make it a pack.

A pack is a folder of profiles in your own repository. List it on the hub with one pull request, and everyone gets a pinned command.

Publish a packRead the author guide
  1. Tag a release in your pack's repository: git tag v1.0.0
  2. Add it to the index: uv run pytemplate_hub add https://github.com/<you>/<pack> --tag v1.0.0 --license MIT
  3. Open the pull request. CI checks the pack, a maintainer merges, and it appears here.
